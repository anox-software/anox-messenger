## B. State Inventory

- `anox_state_key.enc` — wrapped local protection key, app-private files directory.
- `anox_identity.enc` — protected vodozemac identity account pickle.
- `anox_session.enc` — protected vodozemac session pickle.
- No plaintext copies of any of the above.

## C. Generation Rules

1. **Keystore key**: created once on first `getOrCreateStateKey()` via `KeyGenerator` with `AES/GCM/NoPadding`, 256-bit, `AndroidKeyStore`, `setUserAuthenticationRequired(false)` for V1.
2. **State key**: generated with `SecureRandom` only if `anox_state_key.enc` does not exist. Exactly 32 bytes.
3. **E2EE identity**: generated only through `createAndPersistFirstIdentity` or explicit `createIdentity`. Must not silently replace an existing `anox_identity.enc`.
4. **Olm session**: generated by `create_outbound_session` or `create_inbound_session` after a valid identity and keys are present.

## D. Persistence Rules

- All protected files use the versioned envelope described in Section E.
- Files are written with an **atomic temp-file + fsync + rename** pattern.
- All state-changing storage operations are serialized by a `ReentrantLock` in `CryptoBridge`.
- Files are located in the app-private `context.filesDir`.
- `allowBackup="false"` in `AndroidManifest.xml` prevents cloud restore.

## E. Envelope Format

Protected-state binary format:

```
[ 4 magic bytes "ANOX" ]
[ 1 version byte 0x01 ]
[ 12 nonce bytes ]
[ ciphertext + 16-byte GCM authentication tag ]
```

- Magic and version are authenticated via GCM AAD.
- Unknown version is rejected explicitly before decryption.
- Malformed magic is rejected explicitly.
- Truncated or corrupted tag is rejected by AES-GCM authentication.
- Minimum envelope size: 33 bytes.

## F. Keystore Lifecycle

- **Alias:** `anox_crypto_master_key`
- **KeySize:** 256
- **Algorithm:** `AES/GCM/NoPadding`
- **Provider:** `AndroidKeyStore`
- **Extractable:** false
- **Invalidated by:** app data clear, app uninstall, optional device lock changes on some OEMs.
- **Usage:** wrap/unwrap the 32-byte local state key.

## G. State-Key Lifecycle

- Stable for the lifetime of the identity.
- No automatic rotation in V1.
- Generated once per install if absent.
- Wrapped before any persistent storage.
- Destroyed by deleting `anox_state_key.enc` and removing the Keystore key.
- Wrong length (≠ 32) is rejected by Rust `CryptoSerializer::new`.

## H. Identity Lifecycle

- Created by `createAndPersistFirstIdentity` only when no `anox_identity.enc` exists.
- Persisted with `saveIdentity`.
- Loaded with `loadIdentity`.
- Destroyed with `destroyIdentity` and optionally removed by `wipeLocalCrypto`.
- Public keys can be exported; private keys never leave Rust.

## I. Session Lifecycle

- Created by `createOutboundSession` or `createInboundSession`.
- Must be saved after any message that changes the ratchet state.
- `saveSession` / `loadSession` use the same atomic write / versioned envelope.
- `Session` handles are tracked in `ACTIVE_SESSIONS` in Rust.

## J. First-Run / Lost-State Distinction

`CryptoBridge.getLocalStateStatus()` returns:

- `FirstRun` — no state files.
- `IdentityReady(identity)` — valid identity can be loaded.
- `WipedState` — state key exists but no identity file.
- `MissingStateKey` — identity file exists but state key missing.
- `MissingKeystore` — Keystore wrapping key cannot be used.
- `CorruptedIdentityState(reason)` — files exist but authentication/decryption fails.

The crypto layer never silently creates a new identity when an existing identity is unavailable.

## K. Atomic Write Semantics

All protected file writes use:

```text
write to file.tmp
flush
fsync / FileDescriptor.sync()
rename file.tmp → file
```

A failed or interrupted write leaves the previous valid `.enc` untouched.

## L. Corruption Behavior

Load operations fail closed for:

- missing file
- empty file
- truncated envelope
- invalid magic
- unsupported version
- modified nonce/ciphertext/tag
- corrupted wrapped state key
- missing Keystore key
- wrong state key
- invalid key length

Result is a `CryptoResult.Failure`; no plaintext, no secret exposure, no silent identity replacement.

## M. Logout / Wipe / Delete

- **Logout (future):** remove future API tokens; E2EE local state remains.
- **Wipe:** `wipeLocalCrypto()` deletes Keystore alias, wrapped state key, identity, and session files.
- **Account Delete:** same local wipe path plus future server revocation.

## N. Backup Policy

- `allowBackup="false"` in `AndroidManifest.xml`.
- No custom backup rules for crypto state.
- Private E2EE state must never be restored from cloud, Seedvault, D2D, or Google backup.

## O. Concurrency Model

- A single `ReentrantLock` in `CryptoBridge` serializes state-changing operations.
- Future messaging must acquire this lock when reading or writing session state.
- No concurrent `save`/`load` can produce a partially written or torn identity/session file.

## P. Known Limitations

- Keystore/TEE availability varies by device; on some devices the Keystore may be software-backed.
- Atomic write is best-effort at the filesystem layer; no guaranteed physical flash-sector erasure.
- No explicit state envelope version existed before PROMPT-006; old unversioned development data is not migrated.
- GrapheneOS-specific runtime validation is pending.

## Q. Migration Rules

- Old unversioned `[nonce][ciphertext+tag]` development data is **not** migrated.
- Any pre-PROMPT-006 protected files are treated as corrupted/unsupported and fail closed.
- New installs and new persistence use the versioned `ANOX`/`0x01` envelope.

## R. Security Invariants

- No account or crypto recovery in V1.
- Private E2EE state stays on the device.
- Server never receives E2EE private keys or plaintext.
- Keystore wrapping key is not the E2EE identity.
- No custom cryptographic primitives.
- No plaintext secrets in logs.
