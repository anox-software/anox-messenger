## 1. Model

Each invariant row records:

- **invariant_id / source** — `INV-NN` bound to the ordinal in `SECURITY_INVARIANTS_V1_1.md`.
- **domains** — affected B-domains.
- **enforcement_surfaces** — where the invariant is expected to be enforced (`ARCHITECTURE_GOVERNANCE`, `CLIENT_ANDROID`, `RUST_CRYPTO`, `BACKEND_B004`, `DB_B005`, `API_B007`, `LOCAL_STORAGE_B009`, `INFRA_B016`, `REPO_CI_B017`, `RELEASE_GOVERNANCE`, `DOCS_COPY`).
- **verification_ids** — stable test IDs from the B-021 matrix plus the per-invariant check `ANOX-TEST-INV-NN`.
- **Dimensional state fields** — recorded independently so they can never collapse into one flag:
  - `implementation_state`: `NOT_APPLICABLE` / `NOT_STARTED` / `PARTIAL` / `IMPLEMENTED`
  - `automated_state`: `NOT_APPLICABLE` / `NOT_RUN` / `PARTIAL` / `PASS` (PASS requires `automated_evidence`)
  - `physical_state`: `NOT_APPLICABLE` / `REQUIRED_PENDING` / `VERIFIED`
  - `external_state`: `NOT_APPLICABLE` / `REQUIRED_PENDING` / `VERIFIED`
- **verification_state** — highest attained rung: `SPECIFIED` < `IMPLEMENTED` < `TESTED` < `PHYSICALLY_VERIFIED` < `EXTERNALLY_VERIFIED`.
- **evidence_state** — `NOT_APPLICABLE` / `SPEC_ONLY` / `IMPLEMENTED_UNVERIFIED` / `AUTOMATED_VERIFIED` / `PHYSICAL_VERIFICATION_REQUIRED` / `EXTERNAL_REVIEW_REQUIRED` / `VERIFIED` (mapped to B-027 E0–E4 in V1.3 §Security Invariant Traceability).
- **pre_product_gate / release_gate** — gate applicability.

## 2. No false verification

Specification correctness is never implementation or verification evidence. `B-004 spec exists` ≠ backend implemented; `B-005 schema frozen` ≠ SQL/RLS deployed; `StrongBox requirement exists` ≠ physical StrongBox verified. `NOT_RUN`, `BLOCKED`, and `UNVERIFIED` never count as PASS in any gate.
